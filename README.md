# docRenderCut

业务单据**标准模板渲染 + 模板块裁剪**的前后端项目。

解决的问题：业务方给的一批扫描件（PDF / 图片）规格不一，按固定坐标裁剪目标字段总会出现
"有的裁全、有的裁一半、有的完全裁不到"。本项目为每个单据类别建立一个**标准模板**，
所有输入都渲染进同一个坐标系，于是在模板上量一次坐标，之后任何输入都用同一组坐标裁剪。

已实测：同一类别的 30 页输入，用同一组固定坐标裁出的「付款金额」块，表格边框与栏目
逐像素重合，只有填写内容不同；块位移 P50 **0.23px**。

依赖：Python 3.9+（无需系统级安装，全部依赖在 `requirements.txt`）。

```bash
# 1. 安装依赖（只需一次）
pip install -r requirements.txt

# 2. 启动
python app.py

# 浏览器打开 http://127.0.0.1:8848
```

## 数据目录（与项目解耦）与多实例部署

**数据不放在项目目录里**。默认是 `<项目>/data`，但生产部署应指向一个外部 / 共享目录，
这样项目本身可以随时替换、升级、多副本部署，而数据只有一份。

优先级：`--data`  >  环境变量 `DOCRENDERCUT_DATA`  >  `<项目>/data`

```bash
# 方式一：命令行（最直观）
python app.py --data D:/drc-shared-data

# 方式二：环境变量（适合写进服务/容器编排）
set DOCRENDERCUT_DATA=\\fileserver\shared\docRenderCut   # Windows
export DOCRENDERCUT_DATA=/mnt/shared/docRenderCut        # Linux

# 方式三：同机多实例，各占一个端口，共用一份数据
python app.py --data D:/drc-shared-data --port 8848
python app.py --data D:/drc-shared-data --port 8849
```

启动时会打印实际使用的数据目录；`GET /api/health` 也会返回 `data` 字段，
多实例排障时先确认它——"以为在看同一份数据、其实各看各的"是这类部署最常见的坑。

### 并发安全

多个实例读写同一个数据目录是支持的，做法是**ID 分配用 mkdir 原子占位**：

- 分类 `CATyyyymmdd-NNNN` / 模板 `TPLyyyymmdd-NNNN` / 任务 `JOByyyymmddHHMMSS-XXXX`
  都不是"扫描目录挑空号"，而是直接 `mkdir` 目标目录——成功即占位，冲突就换下一个号。
  `mkdir` 在同一文件系统上是原子的，所以**并发创建不会撞号、不会互相覆盖**（已实测：
  并发 6 个建分类请求拿到 6 个不同 ID）。
- 每个任务写自己的 `jobs/<jid>/`，天然隔离。

**已知边界（文件存储的固有限制）**：两个实例**同时编辑同一个模板的同一个坐标块**
是"后写覆盖"（last-write-wins）。实际部署建议：**配置 / 建模板只在一个实例上做，
其余实例只跑批量上传**，这样完全没有冲突。若以后需要强一致，应换掉文件存储 + 加锁。

## 任务并行与资源上限

页面是**并行**处理的，但并行度和内存都**有界**——线上机器通常还跑着别的服务，
不能让一个批量任务把 CPU 和内存吃掉。

### 三个上限怎么来的

| 机制 | 做法 | 目的 |
|---|---|---|
| **流式分页** | 上传件按页**逐页栅格化**（`iter_batch_stream`），不再一次性把整批页解码进内存 | 内存**与批次总页数无关** |
| **有界在飞** | 提交给线程池的页数不超过 `max_inflight`，到顶就等一个跑完 | 内存 ≈ `max_inflight × 单页大小` |
| **线程封顶** | `cv2.setNumThreads(cv_threads)` | 否则每个 worker 都按 CPU 核数开 OpenCV 线程，叠起来是线程风暴 |
| **任务排队** | `max_jobs`，默认 1，多出来的任务状态为"排队中" | 连点两次上传不会各开一套 worker 让资源翻倍 |

单页 300dpi A4 解码 ≈ **24.9 MB**（实测）。所以 150 页批次如果用旧的全量载入方式，
还没开始算就要 ~3.6 GB；现在峰值稳定在 **~1.1 GB**，与 50 页批次**完全相同**。

### 配置（环境变量，全部有安全默认值）

```bash
DOCRENDERCUT_CPU_BUDGET=0.5      # CPU 预算，默认 0.5（50%）；据此自动推算并行度
DOCRENDERCUT_CORES_PER_WORKER=2.0 # 单 worker 预估占用核数，实测约 1.5，取 2 更保守
DOCRENDERCUT_WORKERS=4           # 直接指定并行度（留空则按上面两项自动推算）
DOCRENDERCUT_CV_THREADS=4        # OpenCV 内部线程上限（每个 worker）
DOCRENDERCUT_MAX_INFLIGHT=5      # 同时在飞页数上限，默认 workers+1
DOCRENDERCUT_RENDER_DPI=300      # 上传件栅格化 DPI（与模板 DPI 一致可省 CPU）
DOCRENDERCUT_MAX_JOBS=1          # 同时运行的任务数，其余排队
```

**自动推算规则**：`workers = CPU核数 × CPU_BUDGET ÷ CORES_PER_WORKER`，封顶 4。

| 机器 | 自动并行度 | 预估 CPU |
|---|---|---|
| 4 核 | 1 | ~50%（不并行） |
| 8 核 | 2 | ~35% |
| 16 核及以上 | 4 | ~20%（20 核实测 25%） |

启动时和 `GET /api/health` 都会显示当前生效值，运维可据此核对：

```json
{"job":{"workers":4,"cv_threads":4,"max_inflight":5,"render_dpi":300,"max_jobs":1},"cpu_cores":20}
```

任务记录里也会带上这次实际用的配置（`job.json` 的 `runtime` 字段），便于事后归因。

### 实测对比（50 页 × 2 模板，20 核机器）

| | 优化前 | 优化后（4 worker） |
|---|---|---|
| 50 页耗时 | 8~16 分钟（4~6 页/分） | **3.3 分钟（15 页/分）** |
| 峰值内存 | 1.87 GB | **1.14 GB** |
| CPU | 2.7/20 核（13%） | 4.9/20 核（25%） |
| 150 页批次峰值内存 | ~3.6 GB（解码即 OOM 风险） | **1.14 GB（与 50 页相同）** |

**每页耗时与分类下模板数成正比**（每页要对每个模板各跑一次完整配准），
且"匹配不上的模板"比"匹配上的"慢约 3 倍。所以分类下模板越多越慢，
建议按约定控制单分类模板数（≤10）。

## 术语：分类（Category）与模板（Template）

模型是**两级**，上传时只选分类，系统按页自动归到某个模板：

```
分类（Category）—— 纯容器，只有名字，**没有任何纸面参数**
  ├── 模板（Template）—— 完整配置：DPI、画布 W/H、纸张处理、深墨偏置、坐标清单
  └── 模板（Template）—— …… 来一个维护一个
```

| 概念 | ID 形如 | 作用 |
|---|---|---|
| 分类 | `CATyyyymmdd-NNNN` | 建分类只是为了"上传时不用拆文件、不用指定模板" |
| 模板 | `TPLyyyymmdd-NNNN` | **配准、渲染、裁剪的执行单元**；坐标清单挂在它下面 |

**为什么要分类**：同一类单据（如"支票"）下有多个银行的版式，内容块位置不同
（二维码在右下 vs 左下、付款账户在左上 vs 中间）。差异大就会分不开，
所以约定**单分类下模板数 ≤ 10**，再多就拆分类。

## 使用流程

### 1. 创建分类

点左侧「+ 创建分类」，只填一个名字（如「支票」）。分类是纯容器，**不带 DPI / 画布等参数**，
那些都在模板上。

### 2. 建模板（两步：探测 → 确认落盘）

在分类标题栏点「+ 新建模板」，弹窗分两步——**上传即落盘是不对的**（改一次参数就要重建一次）：

1. **① 样张**：选文件后**立刻自动识别**（只解析、不落盘），返回类型 / 像素 / 物理尺寸 /
   识别到的 DPI 及来源 / 警告。
2. **② 核对参数**：DPI 与画布 W/H 已按识别结果填好，直接改也行。
   已知物理尺寸时**改 DPI 会联动画布**（200→150 时 1653×2339 自动变 1240×1754）；
   一旦手工改过 W/H 就停止联动，不跟你的输入打架。
3. 点「确认构建模板」才真正落盘。**想换样张重测，重新选文件即可。**

DPI 识别分四级，按可信度降序：图片内嵌元数据 → 按宽高比推断纸张 → PDF 页面尺寸 → 未知。
**带假标签的图会被识破**：若内嵌 DPI 推出的物理尺寸明显不合理（A4 比例的图算出 437×619mm），
就判定元数据不可信、忽略它并给出警告。

> 建模板时会**自动纠偏**（高级选项里可关）：先把样张摆正再建模板。
> 否则模板基准自身带着倾斜，之后每张输入都会被对齐到这个歪的模板上。
> 纠偏后若残余角仍 > 0.3°，会明确警告"样例太糊/线太少，纠偏不可靠"，不静默放过。

### 3. 编辑模板（改参数 / 换样张）

分类标题栏的「编辑模板」打开的是同一个弹窗，只是换了身份：

- **重新选样张 → 立刻重新识别**，DPI/画布自动重填，确认后覆盖原模板并重建。
- 不选新文件 = 沿用原样张，只改参数也成立。
- **只改名字这种不影响渲染的字段 → 不重建**，直接秒存（模板图一个字节都不动）。
- 返回值会给出人话的改动清单（如 `DPI: 150 → 200`）。

⚠️ **重建会保留原有坐标块，但它们是在旧模板上量的**。内容整体转动/缩放后需要逐个核对，
偏了就重框——返回值里会带这条告警。

### 4. 配置模板块坐标

选中分类 → 选模板 → 「模板与坐标」页：

- 在模板图上**按住拖动框选**一块；勾选「吸附表格线」时框边会自动贴到检测到的表格线上。
- **默认不显示任何框**，点右下列表里的某一项才显示它的框（框多了会糊住底图，看不清版式）。
  需要总览时勾选工具栏「全部显示」。
- 选中的框可以直接**拖内部移动坐标**、**拖 8 个手柄改宽高**；
  右侧 X/Y/W/H 与框双向联动，也可以用方向键 ±1px（Shift ±10px）微调。
  越界时**长宽被边界截断**，不会把整个框推走；钳位后失焦会把实际值回写进输入框。
- 精度不够时用缩放滑块（最大 8x）或「1:1」放大，**空格 + 拖动 / 中键拖动平移**；
  鼠标旁实时显示图像坐标。
- 字段 **ID 由后台自动分配**（`field01`、`field02`…，**不可编辑、单调递增不复用**，
  删掉 `field02` 后新建会给 `field04`），你只填**字段说明**（这个 ID 的含义）。
  裁剪产物文件名即 `fieldNN.png`——**下游请按 ID 取，不要按中文名**。
- 「外扩像素」= 实际裁剪时在坐标基础上向外扩的量，用来吸收有界的配准残差。
  **坐标量得准不准**和**留了多少余量**是两件事，分开配。
- 已配置的块在右下列表显示**从模板裁出来的预览缩略图**，一眼看出框得对不对。

### 5. 上传批量生产文件

「批量处理」页**只选分类，不选模板**：

- **PDF 自动分页**（一份 10 页 PDF 产出 10 个页面单元）
- 系统**逐页识别**每页属于分类下哪个模板，按各自模板的规格渲染、按各自坐标裁块
- **识别不出的页进 `rejected`**，原样保留供审计，不产出标准图也不裁块

处理**并行**进行（并行度与资源上限见上文），跑完会清空已选文件避免重复上传。

### 6. 看结果与验证

任务记录 / 批量处理页列出任务；每行第二行直接标出**归属**：分类标签 + 识别到的模板标签
（多页带 `×n`），不用点开就知道"这批是哪个分类、归到了哪些模板"。

点「查看」打开任务弹窗，逐页卡片显示：状态、标准图缩略图、逐块裁剪结果，以及
**「原始分页 PDF ↗」**（配准前的原始页，方便对照"原样 vs 归一化后"）。

点「运行块验证」：把同一块从每一张输出里按**同一组固定坐标**裁出来纵向堆叠，
并逐块给出与模板同坐标区域的**亚像素位移**。堆叠图版式重合 = 坐标真的固定住了；
某行错位 = 那张输入没对齐。

### 7. 任务归属反查

任务归属有**两级**，别混：分类是**任务级**的（一次上传只选一个分类），
模板是**页级**的（一个任务可混多个模板，这正是"混合分页自动识别"的目的）。

| 方式 | 得到什么 |
|---|---|
| `GET /api/jobs/{jid}` | 完整记录：`category_id/name` + 每页的 `template_id/name`、score、输出路径 |
| `GET /api/jobs?category_id=CAT…` | 按分类过滤 |
| `GET /api/jobs?template_id=TPL…` | **按模板反查**：哪些任务用过它 |
| 磁盘 `<DATA>/jobs/<jid>/job.json` | 同上（磁盘即数据库） |

**要注意**：`JOByyyymmddHHMMSS-XXXX` 这个 id **本身不含归属信息**（只有时间戳 + 随机串），
反查靠的是 `job.json`——所以别删它。分类/模板的名称是**建任务时的快照**，改名后仍显示当时的名字
（审计要的正是"当时按什么处理的"），稳定键永远是 id。

## 分类作用域

**「批量处理」和「任务记录」两页都是严格属于某个分类的**——因为这两页本身就是
"往这个分类里写"和"这个分类历史发生了什么"，跨分类混在一起没有意义，还容易误判。

具体做法：

- 两页顶部都有**作用域提示**（`上传目标类别：…` / `只显示类别 … 的任务记录`），
  当前操作落在哪个类别上一眼可见。上传是不可逆的写入，选错类别代价不小。
- 切换类别时**清空**批量页的一切状态：上一次的进度、上一次的逐页结果，
  以及**已选中的待上传文件**（留着的话很容易把 A 类别的文件上传进 B 类别）。
- 切换类别时**自动载入该类别最近一次成功的任务**，而不是留一片空白。
- 全部渲染都带**归属守卫**：任务自身带 `category_id`，与当前选中类别不符时拒绝渲染。
  轮询也一样——上传途中切走类别，任务照常在后台跑完，但结果不会串到别的类别上。
- 模板图**不阻塞页签切换**：模板 PNG 可能很大（实测 3400×1600 要解码一会儿），
  批量页与任务记录页的内容跟它无关，不该等它。

### 深链接

视图会写进 URL，可以收藏、可以直接发给别人：

```
http://127.0.0.1:8848/?cat=CAT20260925-0002
http://127.0.0.1:8848/?cat=CAT20260925-0002&tab=jobs     # tab: tpl | batch | jobs
```

### 模板图的显示与原始尺寸

界面画布上画的是**降采样预览**（`/api/categories/{id}/template.png?max=1800&v=<版本>`），
磁盘上的 `template.png` 始终是全分辨率原图，引擎只读磁盘那一份。

原因：拍照件建的模板，灰度图里带大量纸纹噪声，PNG 压不动——
实测一张 3400×1600 的模板有 **5.7 MB**，浏览器解码要几秒，期间画布一片空白，看着像坏了。
降采样后是 1800px / 637 KB（体积降 8.9 倍），显示上没有任何区别。
编码会在 JPEG 与 PNG 之间**取体积小者**：照片型模板选 JPEG，干净的印刷件模板选 PNG。

坐标拾取的精度不受影响——画布坐标用的是真实画布尺寸，预览图只是被缩放绘制。
要把细节放大到 1:1 以上时，用工具栏的「看原图」打开全分辨率图。

`?v=` 是模板文件的 mtime：重建模板后 URL 变化才会重新下载，
平时刷新页面走浏览器缓存，不会白下几 MB。

## 界面

### 顶栏

顶栏一条就装下了"当前在哪 + 能做什么"，**内容区不再单占一行标题栏**（省约 52px 纵向空间）：

```
银行支票  CAT20260927-0001 · 2 个模板  [+ 新建模板] [编辑模板] [删除模板] [删除分类]   …   [数据目录] [服务正常]
```

窄屏按「分类元信息 → 压缩标题宽度」逐级让位（≤1300px 隐藏元信息，≤1120px 标题限宽）。
未选中分类时不显示这一段。

### 模板与坐标（坐标标注器）

**默认不显示任何框**，底图看得清；点右下列表里的某一项才显示它的框。框支持：

| 操作 | 效果 |
|---|---|
| 在空白处拖动 | 新建一个框（自动吸附表格线） |
| 拖框内部 | 移动坐标（宽高不变） |
| 拖框边上 8 个方块 | 改宽高；拖出画布边界时**停在边界**，不会把框整体推回去 |
| 改右侧 X/Y/W/H | 框立刻跟着移动或变形（双向联动） |
| 方向键 / Shift+方向键 | 坐标 ±1px / ±10px 微调 |
| 鼠标悬停列表项 | 画布上高亮对应框 |
| 工具栏「全部显示」 | 一次看全部框，用于检查整体布局 |
| 缩放滑块 / 1:1 / 空格拖动 | 放大精修与平移（最大 8x），鼠标旁实时显示图像坐标 |

虚线绿框是**外扩后的实际裁剪框**（真正交给下游的范围），实线蓝/绿框是你量的坐标；
绿色表示有未保存改动。拖动和输入都只改本地状态，点「保存该块」才落盘——
拖一下就自动写库太容易误改，而这份坐标清单没有撤销。

### 批量处理

一次上传一批文件（**只选分类**）；PDF 自动分页、图片按模板渲染，系统逐页识别归属。
页面的「任务记录」列表每行第二行标出分类 + 识别到的模板，点「查看」打开弹窗看逐页卡片
（标准图、逐块裁剪、原始分页 PDF）。

### 任务弹窗与验证

### standardized/ 的两个子目录

| 目录 | 内容 | 用途 |
|---|---|---|
| `standardized/image/` | 配准到标准画布后的图（PNG，按模板 DPI） | **切片任务读这里**，块坐标就是在这张图上量的 |
| `standardized/pdf/` | **配准前**的原始页，每页一个单页 PDF | 给消费者查看原始分页；与是否识别成功无关 |

**为什么 pdf/ 要放在 standardized/ 里而不是单独顶层**：消费者拿到的是一份任务的完整产物，
原始页与标准图并排放在一起，对照"原样 vs 归一化后"最直观。

**单页 PDF 是无损的**（实测回读逐像素一致，最大差 0）。编码选型实测：

| 编码 | 干净数字票 | 带噪扫描件 | 说明 |
|---|---|---|---|
| Pillow 存 PDF（L/RGB） | — | — | 走 JPEG，**有损**（实测最大差 25）→ 不用 |
| PyMuPDF 原始位图（默认） | 24.9 MB/页 | 24.9 MB/页 | **不压缩**，等于裸位图 → 不用 |
| PyMuPDF + `deflate`，DeviceGray | 0.68 MB | 2.16 MB | 无损 |
| PyMuPDF + `deflate`，DeviceRGB | 1.27 MB | 3.64 MB | 无损，**默认** |

真实扫描件常带**轻微色偏**（实测通道差最大 19，肉眼看仍是黑白件），色偏不含信息
却让体积多花约 70%。所以提供开关：

```bash
DOCRENDERCUT_PAGE_PDF=original   # 默认：忠实原样（有彩色就用 RGB）
DOCRENDERCUT_PAGE_PDF=gray       # 强制灰度：去掉色偏，体积省约 40%、快约 3 倍
DOCRENDERCUT_PAGE_PDF=off        # 不产出原始分页 PDF（只要标准图时）
```

页内原始页的链接在任务详情的每张页卡片上（「原始分页 PDF ↗」），
接口里对应每页记录的 `pdf_url` 字段。

## 状态与判读

| 状态 | 含义 | 处理 |
|---|---|---|
| `ok` | 配准通过且残余倾斜在界内 | 直接用 |
| `low_confidence` | 出图了，但**对齐后残余倾斜超界**（默认 > 0.35°），坐标会有随位置放大的偏移 | 输出在 `low_confidence/`，人工抽检 |
| `rejected` | 结构相关度过低（默认 < 0.25），明显错配 | 原图落在 `rejected/`，不产出标准图 |

**为什么质量判据是"残余倾斜"而不是"结构相关度"**：结构相关度随输入分辨率单调下降，
它度量的是"输入有多清晰"而不是"配准准不准"。同一批样本实测：300dpi 相关度 0.97、
72dpi 只有 0.29，而两者真实坐标残差都是 0.5px 量级；更糟的是，一张坐标偏了 10px 的
照片相关度 0.45，反而**高于**配准正确的 72dpi 页（0.27）。残余倾斜没有这个问题——
内容歪了就是歪了。实测分离度：合格页 0.000°~0.239°，出问题的页 0.94°~1.40°。

## 已知边界

1. **拍照件需要手工四角**。纸张边界自动检测在真实照片上不可靠：阴影会让纸面在灰度上消失，
   桌面木纹与票据防伪底纹都是"长边缘"。在创建类别时选「手工指定四角」并给出
   `x1,y1,x2,y2,x3,y3,x4,y4`（左上,右上,右下,左下）。
2. **推荐输入分辨率 ≥ 150dpi**。低于此结构线只剩 1~2px，个别页会失效
   （实测 72dpi 有一页坐标误差 23.8px，该页会被验证环节抓到）。把低分辨率图放大到画布
   不增加任何细节——真正的杠杆是重新采集。
3. **内部门禁过关不等于坐标正确**。有一类失效（低分辨率下单轴观测不足）内部门禁漏过，
   靠「运行块验证」兜底。所以第 4 步不能省。
4. **画布宽高比要与样张一致**，否则内容被非等比拉伸。界面会警告。
5. **真实扫描件的验收还没做**。目前的量化结果来自合成样本（验证的是几何配准精度），
   真实件的纸张变形、进纸非线性倾斜、折痕、印章手写压线都还没测，阈值需要重标。
6. **坐标清单与模板绑定**。重建模板后坐标需要重新核对——界面会提示，但不会替你判断。
